## 1. Почему ветвление в Git «дешёвое», а в SVN — «дорогое»?

- **Git:** ветка — это просто указатель на коммит. Создание — мгновенно и **локально**, без сети.
- **SVN:** ветка — это копия директории в **центральном** репозитории. Создание требует связи с сервером (`svn copy`), слияния сложнее и тоже фиксируются на сервере.
- Итог: в Git ветки создают часто и живут они недолго; в SVN — редко и долго.

## 2. Можно ли в SVN сделать коммит без интернета?

**Нет.** SVN централизован: вся история и все изменения — на сервере. Коммит сразу требует связи с ним.

В Git — **да**, потому что репозиторий полностью локальный; сеть нужна только для `push`/`pull`.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- **Большие бинарные файлы** (видео, 3D, прошивки): SVN позволяет checkout только нужной части, Git тянет всю историю.
- **Жёсткий контроль доступа и блокировки файлов** (директориальные права, exclusive locks) — важно, когда файлы нельзя сливать автоматически.
- **Аудит и compliance** (например, ISO 26262): сквозная нумерация ревизий и централизованная история удобнее для проверок.
- **Наследие**: годами работающая инфраструктура SVN — миграция дороже, чем остаться.
